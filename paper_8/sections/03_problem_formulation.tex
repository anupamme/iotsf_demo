% ============================================================
\section{Problem Formulation}
\label{sec:problem}
% ============================================================

\textbf{Setting.}
Given a pre-trained time-series foundation model with encoder
$f_\theta: \R^{T \times F} \to \R^d$ and a downstream dataset
$\mathcal{D}$ of size $n$, fine-tuning produces updated parameters
$\theta'$ by minimising a task loss (NLL for forecasting; NLL+SupCon
for anomaly detection).  We measure what happens to the encoder's
pre-trained features during this update using three diagnostics
(\S\ref{sec:method}): CKA between $f_\theta$ and $f_{\theta'}$
(geometric similarity), a linear probe $R^2$ onto the downstream
target (\emph{relative linear-decodability}: we report
$\Delta R^2 {=} R^2(\text{FT}){-}R^2(\text{ZS})$, and note that
$R^2(\text{FT})$ itself remains \emph{absolutely negative} in our
setting --- see \S\ref{sec:analysis} and App.~\ref{app:probing}), and the $\ell_2$ weight drift
$\|\theta' - \theta\|_2$.

\textbf{Pre-training value gate.}
Studying whether fine-tuning ``destroys valuable pre-trained
features'' requires a domain where such features are demonstrably
present.  We set the gate at zero-shot MSE 20\% below a Linear
baseline (\S\ref{sec:forecasting:gate}); ETTh1/ETTh2/ETTm2 at
$h{=}96$ pass with Moirai-Small.  Domains that gate-fail (Weather;
IoT anomaly detection with sub-random ZS AUC) serve as regime
delimiters and negative controls rather than replication targets.

\textbf{Task-level consequence: forgetting.}
We define forgetting as the signed relative change in the
zero-shot-canonical task metric on a held-out test set:
$\text{forg.\%} = 100 \cdot (M_{\text{FT}} - M_{\text{ZS}}) /
|M_{\text{ZS}}|$ (MSE for forecasting, so positive = worse;
1\,$-$\,AUC for IoT).  Forg.$>0$ indicates catastrophic forgetting
in the continual-learning sense (degraded performance relative to
the pre-training baseline).
